installing ninit

small init for linux. one file per service, a dependency graph compiled ahead of boot, cgroup tracking and a control socket. current release 1.0.1

gentoo 
emerge --ask app-eselect/eselect-repository
eselect repository add nburch git https://github.com/noahburchell/nburch-overlay.git
emaint sync --repo nburch
emerge --ask sys-apps/ninit

the use flags are o3, lto, native, quiet, authshell, busybox, tools and debug. they map to the configure options below. ninit selects its own optimisation flags from them, so CFLAGS and LDFLAGS in make.conf are ignored. example service files are installed to /usr/share/doc/ninit-*/ninit.d

source

linux only. make is required. the source is c23, so gcc 14 or newer, or clang 18 or newer

get the source

the release tarball

curl -LO https://github.com/noahburchell/ninit/releases/download/v1.0.1/ninit-1.0.1.tar.xz
tar xf ninit-1.0.1.tar.xz
cd ninit-1.0.1

the source code archive on the tags page contains no configure script and has to be bootstrapped with ./autogen.sh first

build it

./configure --prefix=/usr
make -j"$(nproc)"
sudo make install
sudo make tools-install

--prefix=/usr is correct for a system install. tools-install is optional and is described under shutting down

out of tree builds work and leave the source directory clean

mkdir build && cd build && ../configure && make

make V=1 prints the plain automake recipe. for an initramfs, link it statically with ./configure LDFLAGS=-static

configure options 
--enable-o3            -O3 instead of -O2
--enable-lto           link time optimisation
--enable-native        -march=native
--enable-quiet         only WARN and FAIL on the console during boot
--enable-authshell     run sulogin for recovery when root has a usable password
                       hash, plain shell when it doesn't
--with-busybox[=PATH]  try busybox before /bin/sh for the emergency shell
--with-shell=PATH      the interpreter service scripts are written for
--with-shell-name=NAME what to call it
--with-service-dir=DIR where service files live, default /etc/ninit.d
--enable-werror        turn warnings into errors
--enable-debug         -O0 with ASan and UBSan, testing only, never pid 1

service scripts are compiled as programs for /bin/bash. there is no fallback to another shell, because the same text under a different shell is a different program. --with-shell=/bin/dash --with-shell-name=dash changes the interpreter

service files

each service is one file in /etc/ninit.d, named after the service. the file is a bash script. directives are #%key: value comments. every directive must precede the first command. a directive placed after code is an error

#!/bin/bash
#%type: daemon            oneshot (default), daemon, or target
#%depon: fs, udev         services that must be complete first
#%depof: multi-user       services that must wait for this one
#%onfail: stop            warn, stop, shell
#%restart: always         daemon only: respawn after it has reported ready
#%notify: 3               daemon only: ready once it writes a newline to this fd
#%start-timeout: 90s      how long it may take to become ready (default 90s)
#%stop-timeout: 5s        how long it gets after SIGTERM before SIGKILL (5s)
#%start-tries: 2          attempts before onfail decides (oneshot 1, daemon 2)
#%start-delay: 0s         wait between those attempts (default none)
#%deps: uptime            uptime (default) or order

durations take ms, s, m or h, or a plain count of milliseconds

a oneshot service is complete when it exits 0. a daemon is complete when it writes a newline to its notify fd, or immediately after spawn when it has none. a target has no commands and is complete when its dependencies are

rules

start-tries bounds startup. restart is supervision and begins only after a daemon has reported ready. a daemon that exits before reporting ready is not respawned

deps: uptime permits a dependent to start only while the service is up. deps: order requires only that the service has started once. the directive is set on the service that others depend on

a target goes down when anything behind it dies, and so does everything waiting on it. with no onfail directive the default is stop when another service depends on this one and warn when none does

each service gets its own cgroup under /sys/fs/cgroup/ninit.services and is killed with cgroup.kill, so setsid() does not escape it. on linux 5.7 and later a service is forked directly into its cgroup, otherwise it joins immediately after the fork. without cgroup v2 ninit falls back to the process group and reports that it has done so

services run with stdin on /dev/null, stdout and stderr through ninit, and only PATH, HOME=/ and TERM=linux in the environment. each runs in its own session with no controlling terminal. console output is prefixed with the service name, and the last KiB is printed on failure

daemons

a daemon must remain in the foreground. exec the real binary with the flag that suppresses daemonising, usually -n, --nofork or --foreground. a script that forks and returns is recorded as complete and then treated as dead. a readiness probe belongs in a background subshell of the same script, which writes the newline while the main shell execs the daemon

#!/bin/bash
#%depon: tmpfiles-dev
#%type: daemon
#%notify: 3
#%restart: always
{
	SECONDS=0
	while ((SECONDS < 15)); do
		if udevadm control --ping --timeout=1 >/dev/null 2>&1; then
			echo >&3
			exit 0
		fi
		sleep 0.05
	done
	echo "udev: no ping reply in 15s, reporting it up unverified" >&2
	echo >&3
} &
exec 3>&- /sbin/udevd

a shell on the console has to acquire the tty itself. a getty does this already

#%type: daemon
exec setsid -c bash -i < /dev/console > /dev/console 2>&1

further examples are in docs/ninit.d. they are written for one machine and are not meant to be booted unmodified

ninitctl

the graph is compiled from the service directory, and has to be recompiled after every change to a service file

ninitctl init -n         # check everything, write nothing
ninitctl init            # compile /etc/ninit.d into /etc/ninit.d/depgraph
ninitctl show -v         # print the compiled graph and scripts
ninitctl add|del NAME... # move services between /etc/ninit.d and /etc/ninit.d/unused

init validates each script with bash -n before publishing, so a syntax error is reported at build time rather than at boot. --no-check skips the validation. one exclusive lock covers reading and publishing, and add and del take the same lock, so a build always observes one coherent revision of the directory

the runtime commands use /run/ninit/control and require root

ninitctl status [NAME]   # what ninit is running
ninitctl log             # failures ninit recorded
ninitctl start NAME      # start it, or retry it after a failure
ninitctl stop NAME       # stop it and keep it stopped
ninitctl restart NAME    # restart it
ninitctl resume          # retry every failed and skipped service

an operation is owned by the service rather than by the connection that requested it, so killing the client does not leave a stop half applied. a service counts as stopped when its whole cgroup is empty, not when its main process has exited

ninit reads the graph once at boot. a recompiled graph takes effect at the next boot, and resume retries with the graph already loaded

console output is dropped when it cannot keep up. failure lines are also kept in a small ring that ninitctl log reads back, which is where a failure reason is recorded when the console lost it, or when ninit was built with --enable-quiet

the depgraph format is versioned and checked exactly. run ninitctl init after upgrading ninit and before rebooting. an older graph is refused and the boot enters the emergency shell

shutting down 
kill -TERM 1   # reboot (also ctrl-alt-del)
kill -USR2 1   # poweroff
kill -USR1 1   # halt

busybox reboot, poweroff and halt send the same signals

services are stopped in dependency order across the whole graph. a service is not signalled until everything depending on it has gone. independent branches stop in parallel, and each service gets its own stop-timeout before SIGKILL. ninit then SIGTERMs whatever is left, waits 5s, SIGKILLs, syncs, and remounts filesystems read-only

tools/shutdown.c builds one binary that answers to shutdown, poweroff, halt, reboot and telinit by inspecting argv[0], the way sysvinit and busybox do. on gentoo it is controlled by USE=tools, which is enabled by default

make tools-install   # save the originals as NAME.old, install ours
make tools-uninstall # put the originals back

reboot is shutdown -r, poweroff is shutdown -h, and halt is shutdown -H. telinit accepts only 0 and 6. TIME is now, +MINUTES or HH:MM. a delayed shutdown waits in the foreground and is cancelled with ctrl-c. -f bypasses ninit and calls reboot(2) after a sync

root signals ninit directly. an unprivileged caller asks elogind over D-Bus through dbus-send and polkit decides, which is what systemd's own poweroff does

when pid 1 is not ninit the binary hands over to the saved NAME.old binary, so it can stay installed on a machine that also boots another init. tools-install does not overwrite an existing NAME.old, so running it twice is safe, and it leaves /sbin/init alone. a desktop does not need any of this directly

emergency shell

the emergency shell runs when the graph is missing or corrupt, or when a service with onfail: shell exhausts its start-tries. it is a root shell on the console and is respawned when it exits. it is /bin/sh, or busybox when ninit was built with it. ninit does not block while the shell runs, and ninitctl works from it

by default the shell is unauthenticated, which is the same bargain sysvinit and busybox make. --enable-authshell puts sulogin in front of it when root has a usable password hash. a serial console or a BMC should be treated as a root credential

booting with it

write the service files into /etc/ninit.d and compile them

sudo ninitctl init -n   # fix anything it reports
sudo ninitctl init      # compile the graph

for the first boot, leave the existing init installed and select ninit on the kernel command line rather than replacing /sbin/init

init=/sbin/ninit
